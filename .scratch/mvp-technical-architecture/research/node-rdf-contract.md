## Parsing and graph isolation

For only Turtle plus one standard single-graph format, use strict `N3.Parser` formats `text/turtle` and `application/n-triples`. N3's default parser is a permissive superset that also accepts TriG and N-Quads, so set `format` explicitly. Calling `parse(text)` without callbacks returns a quad array; callback parsing emits quads incrementally. Retag the default-graph quads to the caller's target graph only after parsing succeeds. [N3 parsing API](https://github.com/rdfjs/N3.js/blob/main/README.md)

`rdf-parse` is useful when the accepted media types need to be discovered or broadened. Its `parse` method consumes a caller-provided stream; its `path` option only chooses a parser from the filename/URL suffix and does not open that path. The broader parser set has a real network edge: the Comunica JSON-LD actor accepts an HTTP mediator to fetch remote JSON-LD contexts. Keep an exact MIME allowlist and local loader policy if using it. [rdf-parse source](https://github.com/rubensworks/rdf-parse.js/blob/master/lib/RdfParser.ts), [JSON-LD actor](https://github.com/comunica/comunica/blob/9d61a8d667bc12e9a8d773bb6d4b487817b1e878/packages/actor-rdf-parse-jsonld/README.md)

Do not parse into the active project store. Stage parsed quads in a temporary store and replace the target graph only after full parse completion. This protects against a stream that emitted valid prefix quads before reporting a malformed suffix; RDF/JS `DatasetCore` has no transaction operation. [RDF/JS DatasetCore API](https://rdf.js.org/dataset-spec/#datasetcore-interface), [rdf-parse stream API](https://github.com/rubensworks/rdf-parse.js/blob/master/README.md)

## Query contract and pre-execution gate

Use `QueryEngine.queryBindings()` with `sources: [rdfjsStore]`; Comunica documents strings in `sources` as URLs. Supply only in-memory RDF/JS source objects. For typed parameters, create an RDF/JS `Bindings` with `BindingsFactory.fromRecord`, using `DataFactory.literal(value, datatype)` or another RDF term. Results are bindings whose values remain RDF terms. [RDF/JS querying](https://comunica.dev/docs/query/advanced/rdfjs_querying/), [context and initial bindings](https://comunica.dev/docs/query/advanced/context/)

`unionDefaultGraph: true` adds the union of **all** named graphs to the default graph. To restrict it to ontology/model graphs while retaining named-graph patterns, build a query-only RDF/JS view containing the permitted named quads and duplicate only allowlisted ontology/model quads with `defaultGraph()`; run with `unionDefaultGraph: false` and `sources: [view]`. This preserves `GRAPH <g>` access to permitted named graphs without relying on a selected-union engine option. [Comunica context](https://comunica.dev/docs/query/advanced/context/), [RDF/JS DatasetCore](https://rdf.js.org/dataset-spec/#datasetcore-interface)

Traqula 1.4.0 is a maintained parser candidate: its released parser builder combines query and Update grammar, and its AST discriminates `type: 'query'` from `type: 'update'`. Query ASTs expose `datasets.clauses` with `default`/`named` clause types; SERVICE is a nested pattern with `subType: 'service'`. Before any engine call: require a SELECT query (`type === 'query'`, `subType === 'select'`), reject nonempty dataset clauses (both `FROM` and `FROM NAMED`), and recursively reject any `service` pattern. This also blocks the Update root (including `LOAD`) before it reaches Comunica. Apply the same check to every SHACL `sh:select` after its declared prefixes are applied, before validation, because shacl-engine executes those strings internally. [Traqula parser source](https://github.com/comunica/traqula/blob/1717f3d9abc3c7e500e555f5b9523ce44850ea45/engines/parser-sparql-1-1/lib/Parser.ts), [AST types](https://unpkg.com/@traqula/rules-sparql-1-1@1.4.0/dist/esm/lib/Sparql11types.d.ts), [SPARQL dataset and SERVICE grammar](https://www.w3.org/TR/sparql11-query/), [SPARQL Update](https://www.w3.org/TR/sparql11-update/)

## Network and SHACL boundaries

Network-capable paths found: a URL string in Comunica `sources`; SERVICE in the full RDF/JS engine (Lite explicitly excludes it); JSON-LD remote contexts when the rdf-parse actor is enabled; and SPARQL Update operations such as `LOAD`. Reject SERVICE and every Update before execution, reject dataset clauses as policy, pass only local source objects, and limit imports to Turtle/N-Triples. `FROM` and `FROM NAMED` are not fetches in the RDFJS FromQuad actor: it treats their targets as graph elements in quads; reject them to prevent queries from overriding the selected dataset. [FromQuad actor](https://github.com/comunica/comunica/blob/9d61a8d667bc12e9a8d773bb6d4b487817b1e878/packages/actor-query-operation-from-quad/README.md), [Comunica Update LOAD actor](https://github.com/comunica/comunica/blob/9d61a8d667bc12e9a8d773bb6d4b487817b1e878/packages/actor-query-operation-update-load/README.md), [SPARQL LOAD](https://www.w3.org/TR/sparql11-update/#load). The shacl-engine SPARQL helper itself constructs a local `DatasetSource` and uses Comunica Lite, which excludes SERVICE. [Comunica context](https://comunica.dev/docs/query/advanced/context/), [Lite README](https://github.com/comunica/comunica/blob/master/engines/query-sparql-rdfjs-lite/README.md), [shacl-engine SPARQL helper](https://github.com/rdf-ext/shacl-engine/blob/master/lib/sparql.js), [JSON-LD actor](https://github.com/comunica/comunica/blob/9d61a8d667bc12e9a8d773bb6d4b487817b1e878/packages/actor-rdf-parse-jsonld/README.md)

Core validation is enabled by `Validator`; SHACL-SPARQL support requires passing the `validations` map from `shacl-engine/sparql.js`, and SPARQL-based targets additionally use `targetResolvers`. The README marks SHACL-JS and SHACL Advanced Features as unimplemented. [shacl-engine README](https://github.com/rdf-ext/shacl-engine/blob/master/README.md), [SHACL-SPARQL spec](https://www.w3.org/TR/shacl/#sparql-constraints)

## Smallest integrated proof

One in-memory Node script on Node 20.19 or 22.12+ is sufficient; no HTTP server or external data is needed. Use tiny Turtle and N-Triples fixtures plus a shape graph. Parse strictly into a staged N3 store, retag into named graphs, then build the query view with an excluded decoy graph and selected default-graph copies. Assert a `GRAPH` query and a typed `initialBindings` SELECT succeed, while a default-graph SELECT sees selected ontology/model triples and not the decoy. Feed Update, SERVICE, FROM, and FROM NAMED inputs through Traqula and assert each is rejected before `queryBindings`. Validate one SHACL Core violation and one SHACL-SPARQL constraint with both extension maps. Finally parse a valid-prefix/malformed-suffix file and assert the active graph is unchanged after failure.

Engine selection remains open. The smallest parser path skips `rdf-parse`; add it when broader runtime format dispatch is required, with remote-context loading constrained.
