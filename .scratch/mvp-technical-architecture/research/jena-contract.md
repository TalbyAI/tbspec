# Embedded Apache Jena contract

Checked against the latest official release listed on 2026-09-27. Jena is a viable embedded candidate for this contract; this report does not select it as the engine.

## Version and direct dependencies

Use Apache Jena **6.2.0** on **Java 21+**. Declare `jena-arq` for RIOT, datasets, and local SPARQL, plus `jena-shacl` for validation; the 6.2.0 `jena-shacl` POM depends on `jena-arq`. Use `jena-bom:6.2.0` to align versions. Jena core and supporting jars arrive transitively. `apache-jena-libs` also pulls TDB, which this in-memory proof does not need. No Fuseki artifact is required. [Release page](https://jena.apache.org/download/) · [Maven guide](https://jena.apache.org/download/maven.html) · [6.2.0 SHACL POM](https://github.com/apache/jena/blob/jena-6.2.0/jena-shacl/pom.xml)

## Contract findings

- **Graph formats and isolation:** RIOT supports Turtle and N-Triples, both single-graph syntaxes. Select `Lang.TURTLE` or `Lang.NTRIPLES` from an allowlist and parse a local `InputStream` into a fresh staging graph with `RDFParser` and `ErrorHandlerFactory.errorHandlerStrict`; add that graph to its project graph only after parsing succeeds. This application staging step prevents a late parse error from retaining partial triples or discarding earlier valid files. Do not accept TriG/N-Quads if imports must be confined to one assigned named graph. [RIOT input and parser builder](https://jena.apache.org/documentation/io/rdf-input.html)
- **Named graphs and the default union:** Store each project graph under its assigned IRI in an in-memory `DatasetGraph`. Build the query view with `DynamicDatasets.dynamicDataset(defaultGraphs, namedGraphs, base, false)`: set `defaultGraphs` to only the chosen model and ontology graph IRIs, and `namedGraphs` to the project graph allowlist. This gives the default graph a selected union while keeping `GRAPH` access scoped to the allowed named graphs. `GraphOps.unionGraph(dsg, graphNames)` is an alternative read-only selected-graph union when an explicit graph is needed (for example, SHACL data). Avoid the no-argument union helper: it includes every named graph. [DynamicDatasets API](https://jena.apache.org/documentation/javadoc/arq/org.apache.jena.arq/org/apache/jena/sparql/core/DynamicDatasets.html) · [GraphOps API](https://jena.apache.org/documentation/javadoc/arq/org.apache.jena.arq/org/apache/jena/sparql/graph/GraphOps.html)
- **Typed, read-only queries:** Parse through `QueryFactory.create`, allowlist the required query forms (for example, `SELECT` and `ASK`), and execute only with local `QueryExec.dataset(view)`. Supply terms as Jena `Node`s through `QueryExecBuilder.substitution(Var, Node)` / `substitution(Binding)`, preserving datatype and language without interpolating text. In Jena 6, substitution replaces query variables with RDF terms; it is not the removed “initial bindings” behavior that seeds solution rows. Use `VALUES` if a query needs an input solution table. Keep the mutable base dataset and update APIs out of the caller surface. [QueryExec API](https://jena.apache.org/documentation/javadoc/arq/org.apache.jena.arq/org/apache/jena/sparql/exec/QueryExec.html) · [QueryExecBuilder API](https://jena.apache.org/documentation/javadoc/arq/org.apache.jena.arq/org/apache/jena/sparql/exec/QueryExecBuilder.html) · [Jena 6 changes](https://github.com/apache/jena/blob/jena-6.2.0/CHANGES.txt)
- **Rejecting Update, dataset clauses, and `SERVICE`:** `QueryFactory.create` parses queries, not Update requests; never route caller text to `UpdateFactory`/`UpdateExec`. Reject `Query.hasDatasetDescription()` to block both `FROM` and `FROM NAMED`. Reject `ElementService` in the parsed query before building an executor, traversing nested subqueries and `EXISTS`/`NOT EXISTS` expressions too: `ElementWalker` explicitly does not visit those cases automatically. Apply the same policy to embedded SHACL-SPARQL `SELECT`/`ASK` queries before validation. [QueryFactory](https://jena.apache.org/documentation/javadoc/arq/org.apache.jena.arq/org/apache/jena/query/QueryFactory.html) · [Query dataset-description API](https://jena.apache.org/documentation/javadoc/arq/org.apache.jena.arq/org/apache/jena/query/Query.html) · [ElementWalker limits](https://jena.apache.org/documentation/javadoc/arq/org.apache.jena.arq/org/apache/jena/sparql/syntax/ElementWalker.html)
- **Network isolation:** Jena documents `ARQ.httpServiceAllowed=false` as disabling `SERVICE` (default is `true`). Set it in the global ARQ context before validation: Jena 6.2 SHACL-SPARQL validation itself builds ARQ query executions, so a per-caller-query context alone does not cover it. Use only local streams and `Shapes.parse(graph)`, not URL-loading overloads. This Jena setting blocks SPARQL `SERVICE`, not every possible Java/Jena network path; deny process/container egress for a hard no-network guarantee. [SERVICE controls](https://jena.apache.org/documentation/query/service.html) · [SHACL-SPARQL execution in Jena 6.2](https://github.com/apache/jena/blob/jena-6.2.0/jena-shacl/src/main/java/org/apache/jena/shacl/engine/constraint/SparqlValidation.java) · [Shapes API](https://jena.apache.org/documentation/javadoc/shacl/org.apache.jena.shacl/org/apache/jena/shacl/Shapes.html)
- **SHACL and attribution:** `jena-shacl` implements SHACL Core and SHACL-SPARQL. Parse each shapes graph with `Shapes.parse(graph)` and validate via `ShaclValidator.get().validate(shapes, dataGraph)`. Jena entries expose source shape, constraint, focus node, path/value, severity, and messages, but not the named graph containing the shapes. Validate each shapes graph separately and attach its graph IRI to each emitted diagnostic. [SHACL docs/API](https://jena.apache.org/documentation/shacl/) · [ShaclValidator](https://jena.apache.org/documentation/javadoc/shacl/org.apache.jena.shacl/org/apache/jena/shacl/ShaclValidator.html) · [ReportEntry fields](https://jena.apache.org/documentation/javadoc/shacl/org.apache.jena.shacl/org/apache/jena/shacl/validation/ReportEntry.html)
- **Optional inference:** Jena supplies a transitive reasoner for the reflexive/transitive `rdfs:subClassOf` and `rdfs:subPropertyOf` relations. For inferred instance types and propagated super-property statements, `ReasonerRegistry.getRDFSSimpleReasoner()` / `ModelFactory.createRDFSModel` is available; its “simple” RDFS rule set also includes domain/range entailments, while omitting RDFS axioms. Apply it only to the selected model-plus-ontology graph when enabled. [Inference guide](https://jena.apache.org/documentation/inference/) · [RDFS dataset support](https://jena.apache.org/documentation/rdfs/)

## Smallest integrated proof

One in-memory Java smoke test is sufficient: load Turtle and N-Triples fixtures independently into temporary graphs (including a malformed file after a valid one); assign valid graphs to distinct project IRIs; build the selected default/named query view; query a typed literal and prove a sentinel in an unselected graph is invisible; assert Update, `FROM`, `FROM NAMED`, top-level and nested `SERVICE` are rejected before execution; validate one Core and one SPARQL constraint shape graph separately and check diagnostic graph attribution; then rerun one subclass and one subproperty assertion with inference off/on. Run the same forbidden `SERVICE` case inside a SHACL-SPARQL constraint with Jena's global service switch off. This tests the contract without a server or persistent store.

## Limits to carry forward

Jena's default service policy allows `SERVICE`; no-network behavior needs configuration plus an OS boundary. Jena's SHACL report does not identify the source shapes graph by itself. RDFS “simple” mode is broader than subclass/subproperty propagation alone. Parse staging, query-policy recursion, and graph attribution are application responsibilities.
