# macOS process identity contract

## Recommended built-in path

Use Node's `child_process.execFile` with absolute system-tool paths, no shell, and `encoding: 'buffer'`. The identity tuple is the validated `IOPlatformUUID`, raw `kern.boottime` timeval, PID, and raw per-process start timeval. This avoids a native addon or a prototype dependency.

| Read          | Invocation                                                           | Bounds       |
| ------------- | -------------------------------------------------------------------- | ------------ |
| Host ID       | `/usr/sbin/ioreg`, `['-rd1', '-c', 'IOPlatformExpertDevice']`        | 10 s; 64 KiB |
| Boot time     | `/usr/sbin/sysctl`, `['-b', 'kern.boottime']`                        | 10 s; 64 KiB |
| Process start | `/usr/sbin/sysctl -b kern.proc.pid.<pid>` (pass as two argv entries) | 10 s; 64 KiB |

For ioreg, require one canonical UUID value on the exact `IOPlatformUUID` property; Apple defines that key as the platform UUID string. For sysctl, require exit success and exact output lengths: **16 bytes** for boot time and **648 bytes** for the expected full process record. Parse `tv_sec` with `readBigInt64LE(0)`, signed `tv_usec` with `readInt32LE(8)`, and require positive seconds within the exact wire integer range and `0 <= tv_usec < 1_000_000`. For the process record, also require `readInt32LE(40) === pid` and a live status (running, sleeping or stopped) at byte 36. Do not infer identity from command output text or accept a partial/unknown layout. [Apple IOKit key](https://github.com/apple-oss-distributions/xnu/blob/main/iokit/IOKit/IOKitKeys.h#L228-L232).

The documented XNU shape supports the prefix assumptions: a 64-bit caller gets `user64_kinfo_proc`; its `user64_extern_proc` starts with a 16-byte union whose start-time member begins at byte 0, followed by two 8-byte addresses, a 32-bit flag, a status byte, and a 32-bit PID at byte 40. `user64_timeval` contains a 64-bit seconds field and a signed 32-bit microseconds field; its natural size is 16 bytes. These definitions apply to the 64-bit arm64 and x86_64 ABIs. [XNU process structures](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/proc_internal.h#L638-L650), [user64 timeval](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/_types/_user64_timeval.h#L27-L35), [64-bit sysctl selection](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sysctl.c#L804-L824).

XNU emits the process start time and PID into that structure, and implements `kern.boottime` by returning the same 64-bit timeval shape to 64-bit callers. The `sysctl` utility's `-b` option writes raw bytes. For a missing PID, the kernel returns no record and the utility treats the zero-length non-string result as an error; treat nonzero exit or empty output as unavailable/stale and fail closed. [XNU record fill and PID query](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sysctl.c#L1124-L1148), [boot-time sysctl](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sysctl.c#L2740-L2762), [system_cmds raw-output behavior](https://github.com/apple-oss-distributions/system_cmds/blob/main/sysctl/sysctl.c#L1351-L1374).

## ABI and operating limits

The **648-byte full-record length is an expected layout value, not a numeric constant promised by the published XNU header**: XNU chooses `sizeof(user64_kinfo_proc)` at runtime and documents the interface as size-variant. Keep the exact-length and PID-offset checks, reject other sizes, and verify 648 on both the hosted arm64 and Intel macOS CI jobs before shipping. The `kern.proc` interface is SPI; XNU notes it is intended for system tools/libraries and warns that applications have used it erroneously. [XNU size selection and SPI note](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sysctl.c#L804-L823), [SPI warning](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sysctl.c#L897-L912).

`kern.boottime` is a wall-calendar boot timestamp rather than a random boot UUID. XNU explicitly adjusts its boot-time value when the calendar clock is set, so a clock correction can change the identity during a running boot. Treat any mismatch as a new identity (conservative invalidation); do not claim this timestamp is globally unique. `IOPlatformUUID` scopes identity to the reported platform and can be duplicated by cloned virtual machines or changed with platform replacement. The process query is a snapshot and does not pin the process after the command returns. [XNU boottime adjustment](https://github.com/apple-oss-distributions/xnu/blob/main/osfmk/kern/clock.c#L674-L752), [ioreg options](https://github.com/apple-oss-distributions/IOKitTools/blob/main/ioreg.tproj/ioreg.8).
