# tbspec application

This is the isolated production Node 24/TypeScript package. It imports no prototype code. Root dependencies own repository quality tooling; application dependencies and their pinned transitive graph live here.

## Build and run

From this directory:

```sh
npm ci
npm run typecheck
npm run build
node dist/cli.js --help
node dist/cli.js init ./knowledge --base-iri https://example.org/knowledge/ --json
node dist/cli.js llms projects init --json
node dist/cli.js --project ./knowledge graph list --json
node dist/cli.js --project ./knowledge ontology create ontologies/domain.ttl --json
node dist/cli.js --project ./knowledge ontology import dep:tbspec-state-machine ontologies/state.ttl --json
node dist/cli.js --project ./knowledge model create models/concepts.ttl --type data --json
node dist/cli.js --project ./knowledge model create models/examples.ttl --type data --profile concrete --schema models/concepts.ttl --json
node dist/cli.js --project ./knowledge model create models/plan.ttl --type process --json
node dist/cli.js --project ./knowledge model create models/machine.ttl --type state-machine --json
node dist/cli.js --project ./knowledge model schema list models/examples.ttl --json
node dist/cli.js --project ./knowledge shapes create models/examples.ttl --json
node dist/cli.js --project ./knowledge shapes list --source models/examples.ttl --json
node dist/cli.js --project ./knowledge validate models/examples.ttl --json
node dist/cli.js --project ./knowledge validate --json
node dist/cli.js --project ./knowledge config show --json
node dist/cli.js --project ./knowledge dependency inspect --source ../vocabulary --json
node dist/cli.js --project ./knowledge dependency list --json
node dist/cli.js --project ./knowledge web --background --json
node dist/cli.js --project ./knowledge web status --json
node dist/cli.js --project ./knowledge web stop --json
npm test
```

The compiled executable and immutable `starters/0.1.0/` assets form the package runtime. After dependency installation and compilation, initialization needs Node and the platform's built-in process-identity facilities, with no Git or network access. Source tests use Node's TypeScript stripping; installed execution uses compiled JavaScript. `npm pack` builds a local artifact and does not publish it.

Implemented commands are `init`, `status`, `validate`, `impact`, `resource move`, `shapes list/create/remove`, `graph list/show`, `ontology list/show/create/import/remove`, `model list/show/create/import/remove`, `model schema list/add/remove`, `config show`, `config model-type list`, custom model-type removal, `dependency inspect/add/update/rename/remove/support set/support clear/list/show/check/select/clear`, `web`, `web status/stop`, recursive `llms`, help and version. Individual statement editing is available in the browser.

`init [directory] [--base-iri <iri>]` defaults to the working directory. Global `--project <dir>` can select the initialization directory instead of a positional directory. Base IRIs must be absolute and end in `/` or `#`. Every `--json` invocation, including help, version and argument errors, writes one schema-version-1 envelope to stdout. Diagnostics go to stderr. Exits are 0 success/preview, 1 invalidity, 2 arguments/policy, 3 conflict/recovery/acceptance and 4 unavailable/I/O. Initialization reports resulting validity as `unchecked`; run `validate` or `status` to establish full project validity.

## Dependency updates and manual support

`dependency inspect --source <source> [--ref <revision>] [--resource <selector>]` lists the available exact resources. `dependency add <id> --source <source> --kind ontology|model|design [--ref <revision>] [--resource <selector>]` first returns a preview; retry it with `--accepted-preview <fingerprint>` to apply only the content that still matches. `dependency update <id>` also previews first. Apply it with `--apply --accepted-preview <fingerprint>` and include `--accept-impact` when the preview requires acceptance. The CLI reacquires once for application and rejects changes to bytes, parser context, support, inventory, lock output, impact, or captured project revisions before writing. Acceptance covers introduced or worsened errors and affected skipped or unassessable checks; unrelated baseline errors and warning-only changes do not require it. Acquisition, parsing, integrity, and I/O failures remain failures regardless of acceptance.

`dependency support set <id> --target <dep:id/file> --role shacl|design --source <source> --resource <exact-file> [--ref <revision>]` attaches an exact shapes or design resource from a separate source. It first returns a preview and requires the matching `--accepted-preview <fingerprint>` on retry. Support set does not accept `--accept-impact`. `dependency support clear <id> --target <dep:id/file> --role shacl|design --resource <dep:id/support-file>` deactivates only the selected manual association and keeps its snapshot files and selectors. Manual attachments are recorded separately from the main source and survive dependency updates; inactive support stays available offline but no longer participates in interpretation. Distinct active shapes retain source attribution and equal shapes are deduplicated. Design attachments use ordinary whole-design precedence.

`dependency rename <old-id> <new-id>` previews every owned selector, ontology/design choice, lock path, and selector-derived graph identity change. Apply with `--apply --accepted-preview <fingerprint>` to move the exact locked snapshot bytes and update the lock/configuration together. Declared graph IRIs, parser contexts, graph signatures, and interpretation signatures remain unchanged; generated graph identities derived from selectors change and are listed in the preview. Collisions, occupied destinations, malformed configuration, and stale revisions refuse publication. `dependency remove <id>` previews known direct/downstream references in owned and retained locked RDF/configuration plus resulting project validity. Confirm with `--confirm --accepted-preview <fingerprint>`; this removes only the selected addition's lock record, snapshot, and its ontology/design choices. It preserves independent acquisitions, owned references and views, so removal can succeed while reporting the resulting project as invalid. Neither operation cascades into other additions, views, models, or designs.

In the browser's **Dependencies** workspace, preview updates, rename or remove an addition, attach or clear manual support, review downstream diagnostics and apply the session-owned staged bytes. Rename previews list exact selector/choice/path changes and any generated identity changes. Removal previews list known owned/locked references and retained validity; its apply button requires explicit confirmation. Browser apply checks owner, instance, expiry, fingerprint, acceptance flags, and project revisions without fetching the source again. The authenticated operations are `/api/project/v1/dependencies/update`, `/dependencies/rename`, `/dependencies/remove`, `/dependencies/support/set`, `/dependencies/support/clear`, `/dependencies/apply`, and `/dependencies/cancel`.

## SPARQL queries

Use `query list`, `query show <name>`, `query save <name> --file <path.rq> [--parameters <path.toml>]`, `query run (--file <path.rq> | --saved <name>) [--graph <selector>] [--bindings <path.json>]`, and `query remove <name> [--confirm]`. Saved queries live in `queries/<name>.rq` with a version-1 `queries/<name>.query.toml` declaration. A declaration lists only parameters that may be bound; every parameter has a SPARQL variable name, kind (`iri` or `literal`), and required flag, plus an optional literal datatype or language. There are no defaults or text substitutions. For example:

```toml
schema_version = 1

[[parameters]]
name = "customer"
kind = "iri"
required = true

[[parameters]]
name = "label"
kind = "literal"
required = false
language = "en"
```

```json
{"customer":{"kind":"iri","value":"https://example.org/customer/42"},"label":{"kind":"literal","value":"Order","language":"en"}}
```

For example, save `SELECT ?order WHERE { ?order <https://example.org/customer> ?customer; <https://example.org/label> ?label }` and run it with `--saved orders-by-customer --bindings bindings.json`. `query show` and `query list` inspect saved declarations; removal first returns a preview and requires `--confirm` to apply. Missing required values and wrong term kinds return `invalid_arguments` (CLI exit 2). To test other forms, run files containing `ASK { <urn:missing> ?p ?o }`, `CONSTRUCT { ?s <urn:copy> ?o } WHERE { ?s ?p ?o }`, or `DESCRIBE <https://example.org/customer/42>`; a false ASK is a successful result, SELECT omits unbound cells, and result blank nodes use `scope: "result"`.

Without `--graph`, the default graph is the resolved ontology/model union, while support and unclassified resources are accessible only by their exact named-graph IRIs. `query run --file explore.rq --graph ontologies/customer.ttl` loads that selected resource alone as both the default and only named graph. This keeps an isolated query usable when another file is malformed or project ontology choices conflict. For explicit hierarchy exploration, use a SPARQL property path such as `rdfs:subClassOf+`; the query adds no entailment or inferred triples.

The parsed AST gate accepts only SELECT, ASK, CONSTRUCT, and DESCRIBE. Update, nested SERVICE, FROM, and FROM NAMED fail before engine execution. Query execution uses local in-memory RDF/JS sources, makes no acquisition or dereferencing requests, and does not change canonical project files. Saved-query edits use the normal revision-checked transaction path. In the browser's **Queries** workspace, inspect or select a saved query, edit its text and parameter declaration, run ad hoc or saved queries with an optional exact graph and typed bindings, and save or confirm removal. If a saved query changes after inspection, the draft remains available; use **Refresh revision review; keep current draft** to inspect the current file revisions before retrying. Query-specific syntax and policy guidance is available through `query --help` and `llms queries`.

## Shared operations

`showEditor`, `prepareEdit` and `editGraph` in `src/editing.ts` provide complete-graph inspection and revision-checked editing. Open a graph in the authenticated browser and switch between **Complete graph**, **Turtle source**, and **Forms**. The canvas shows IRI/blank-node subjects and resource-valued objects, with an exact selectable edge for each resource-valued triple. Its positions are temporary; no view or presentation file is created. Select a resource to edit individual RDF values or add an exact triple, including new graph-scoped blank nodes. Removing a triple affects only that statement. Source-element deletion is separate: select a resource and use **Preview source-element deletion** to inspect every incident statement and known external reference, then explicitly confirm the reviewed revision. Blank nodes are scoped to that source graph revision. Only reviewed source occurrences are removed; saved views for that source synchronize their exact relationships and presentation records, while other-source, configuration and locked references remain unchanged. Managed graph roots use lifecycle removal, and clearing a form never deletes an element. Individual RDF edits have no CLI command.

Forms recognize exact explicit OWL/RDFS types in ontology and conceptual-data graphs, expose every applicable section and retain generic access to all statements. Ontology individuals use the same exact-term controls. Typed creation offers every declared property available through the resolved vocabulary, including custom properties, and publishes the selected type and initial values together. Initial properties and additional types are checked against that vocabulary; no superclass/inverse/default statements are inferred. Existing values remain editable when vocabulary is missing. Concrete, custom, unclassified and ambiguously classified graphs use generic/source editing. Process/state forms and saved-view synchronization are later slices.

Graph/form operations preserve unknown statements, lexical values, datatypes and language tags, while serialization may change Turtle layout/comments and blank-node labels. An unchanged value preserves the original bytes. Turtle saves preserve the submitted text, including syntactically invalid text; repair syntax before graph/form edits. Parseable semantic invalidity remains saveable with validation diagnostics. Every save binds the captured byte revision and passes through the existing session-owned staged preview and transaction boundary. A stale draft stays visible beside current source until the user explicitly reviews the new revision; another concurrent change still conflicts. Locked snapshots and owned non-Turtle formats are read-only; editable import supplies a Turtle copy. Rendering uses text, without executing source content or acquiring remote data.

Source, statement and creation drafts, including initial values and their captured revisions, stay in this page's memory across workspace sections, graph selection and workspace **Refresh**. Refresh retains the selected graph and never rebases drafts. Saving or discarding one draft leaves the others intact. Unsaved drafts register a browser reload/closure warning; confirming departure discards them, and crashes or server restarts have no recovery guarantee. No draft text is stored in browser storage or project files. Navigation and editor controls are blocked while a save is in progress. Successful saves refresh project status, inventory and selected graph details and clear previous validation results. If post-save inspection fails, the workspace identifies the successful save and reports unavailable status instead of retaining a stale validity claim; inspect before another write.

`authorResource`, `prepareResource` and `publishResource` in `src/authoring.ts` create and import editable ontologies/models through the existing capture and transaction boundary. Creation uses `--iri` or `base_iri` plus the UTF-8 percent-encoded final filename stem without `.ttl`. Owned destinations must be discoverable project-relative `.ttl` paths outside `.tbspec`, Git and dependency directories. Existing files/directories, graph identity collisions, ambiguous or malformed required graphs, stale reads and pending recovery refuse publication. Identity checks capture inventory/file revisions and inspect owned graphs one at a time after releasing the project lock. Unrelated bytes and parsed stores are not retained. Every owned identity must be established, so malformed or unreadable owned graphs still block authoring. Dependency identities come from lock metadata; only the selected source, receiving vocabulary closure, common contract and relevant schemas require dependency bytes and integrity checks. Publication rechecks all captured revisions, including the owned identity scan.

Model creation requires an enabled configured `--type`. Built-in `data` defaults to conceptual; `--profile concrete` creates an individual/value model and accepts repeatable conceptual `--schema` selectors. `process` and `state-machine` create empty descriptive roots, adding `p-plan:Plan` or `sm:StateMachine` only when the selected vocabulary supplies those exact classes. Custom types declare `tbspec:Model`; no mapping is invented for replacement ontologies. The selected ontology's recorded locked closure or explicit local imports supply vocabulary; common metadata remains independent. Every owned root records its receiving type as `tbspec:modelType`.

Editable import accepts a local Turtle/N-Triples/strict RDF/XML file or an available `dep:<id>[/<file-key>]`. Relative local source paths resolve from the project root unless a public caller supplies `cwd`. Remote content must first become a locked dependency. A copy gets a new managed root plus `prov:wasDerivedFrom` and a literal `dcterms:source`. Only managed root declarations, type binding and import/schema associations relocate; business class/property/individual terms and unknown statements retain their exact identities. Existing owned term declarations produce `TERM_IRI_COLLISION` warnings. Model imports preserve compatible source kinds, explicitly select the receiving type, and report missing class/property vocabulary and schema associations. A completed import with those diagnostics succeeds with resulting validity `invalid`; otherwise validity remains `unchecked` and `validationComplete` is false. Run `validate` after import for full constraint validation. Originals and snapshots remain untouched.

The browser uses the same authoring operations. Creation and import preview before application; proposed bytes are staged beneath `.tbspec/previews/<instance-id>/<handle>/` for fifteen minutes, bound to the tab session and server instance. The shared maximum of 100 pending previews is provisional; it does not bound staged bytes or total memory. Responses disclose a random handle, instance ID and exact expiry; restart never restores retained handles. Staging directories inherit user protection through the same runtime permission checks. Application uses those bytes, checks captured project revisions and consumes the preview. Expiry, worker/server restart, another session, consumption, or stale inputs requires a fresh preview. Expiry cleanup runs without another request and waits for any active operation to finish. Failed staging, cancellation, successful publication and detected revision conflicts also clean that preview; shutdown and worker replacement clean their obsolete workspaces, and exclusive startup cleans recognized leftovers from previous instances. Cleanup validates confined paths and artifact names, preserves unknown/linked files and all transaction recovery evidence, and reports `CLEANUP_RETAINED` warnings through authenticated responses or lifecycle logs. Network or worker loss never automatically retries writes: inspect the resulting project and retained recovery evidence before submitting another operation. Changing the authoring form or cancelling invalidates its pending handle. Successful application uses staged transaction publication. The browser exposes model types, profiles, schema selectors, provenance and stable diagnostics.

`inspectProject` in `src/inspection.ts` supplies the same captured records to CLI commands and authenticated HTTP adapters. Each operation captures only its relevant inputs under the short-lived project lock and verifies their revisions before parsing. Configuration reads the manifest and lockfile; graph inspection additionally reads the selected graph and checks filename-associated support presence without reading its bytes. Graph listings discover and read owned `.ttl`, `.nt`, `.rdf` and `.owl` files recursively, excluding dependencies, ephemeral state, Git and dependency directories. Project-wide status and validation additionally read every retained locked file. Configuration and isolated graph inspection therefore remain available when unrelated graph bytes cannot be read. They do not establish whole-project validity or dependency integrity. Separate browser requests can observe different project revisions.

`model show` has the same focused read scope as `graph show`. It retains every conceptual schema IRI and resolves selectors available from configuration/lock metadata without discovering other owned graph identities. A schema IRI may therefore have no owned selector in this response. The browser derives those owned schema links from its existing inventory and reads the selected target when opened; that inventory may be older than the selected graph. There is no persistent identity index or whole-project integrity claim.

Listings retain malformed/unclassified files and report classification problems without guessing a root. `graph show <selector>` accepts an owned path, `dep:<id>` or any exact retained `dep:<id>/<file-key>`, returning expanded selectors, physical paths, revisions, identity, associations, source text and graph-scoped RDF terms. The browser's selector field accepts the same forms, including retained support files. Configuration reports whole-row manifest overrides and project-locked defaults, including disconnected designs. `status` and `validate` report offline validity and explicit coverage. Errors or skipped required checks exit 1; warnings/info alone succeed. Argument, conflict and I/O failures retain their separate exit categories. No inspection fetches remote data.

## Offline validation and support

`validate [selector]` checks syntax, classification, managed vocabulary positions, associations, current view/presentation invariants and SHACL. Selected validation uses the owned identity inventory and only necessary locked prerequisites; whole-project validation and status inspect every retained snapshot. The identity scan retains compact metadata and revisions, reads owned graphs individually, and reloads only the current target's prerequisite closure. Parsed stores are released between targets; changed deferred inputs fail with a revision conflict. Memory still depends on the largest active closure, diagnostic output and project metadata. Malformed prerequisites skip their dependent checks while independent resources and valid shapes continue. Diagnostics retain target selectors, typed RDF identities, source shapes graphs and blockers; source locations appear only when the parser supplies them.

Each shapes graph runs separately over target triples plus explicit effective subclass/subproperty hierarchy. Schema and ontology business triples are excluded. Locked resources keep their source bindings, and ordinary external individual IRIs never trigger acquisition. The supported profile is SHACL Core plus `sh:sparql` SELECT, with local prefix/PATH expansion, explicit `this` projection and pre-binding restrictions. Expanded queries are gated before evaluation; SERVICE/FROM, updates, custom targets/components and unsupported extensions skip the entire source shapes graph. Anonymous source terms use deterministic graph-scoped labels. The pinned engine's complex-path and property-SELECT behavior is adapted in memory; validation persists no inferred statements.

Pattern constraints use the [XPath 2.0 regex contract](https://www.w3.org/TR/2010/REC-xpath-functions-20101214/#regex-syntax), including XML name escapes, Unicode categories/blocks, class subtraction, captures and backreferences, and `imsx` flags. `xspattern` supplies syntax validation; a capture-aware matcher preserves XPath character and case rules that native JavaScript regex changes. Counted quantifiers are validated without expanding their counts into parser instructions. Unicode categories, blocks and case mappings are pinned to Unicode 15.0. Core adapters also preserve code-point string lengths, language matching, qualified counts, closed shapes, property comparisons and independently declared constraints. The regression suite and focused standards review are evidence for these behaviors, not an exhaustive conformance certification or a regex resource ceiling.

`model schema add <concrete-path> <conceptual-selector>` adds declarations alongside the model's ontology. `model schema remove <concrete-path> <conceptual-selector>` compares effective vocabulary before and after removal, including remaining ontologies, schemas and target declarations. The preview reports lost vocabulary roles and their managed references, baseline/introduced/worsened errors, deactivated shape checks, and skipped or unassessable impact. Comparison includes transitively dependent owned resources, views and presentations; selected `validate` retains its usual prerequisite scope. Repeated errors are compared by multiplicity, and unstable anonymous identities make their impact explicitly unassessable. Publication requires `--confirm`; optional `--accepted-preview <digest>` also binds the reviewed bytes. Confirmed removal can succeed with invalid resulting validation. Its response reports affected-resource validation separately from whole-project validity. Required malformed rewritten graphs and revision conflicts prevent publication. Unknown RDF statements survive the rewrite.

Schema association changes serialize the model as Turtle with deterministic file-local blank-node labels. RDF statements are preserved, but prefixes, comments and original formatting are not retained. Removing an association that is absent fails with `ARGUMENT_INVALID` without rewriting the file.

`shapes create <source-path>` creates an empty associated `.shacl.ttl` without overwriting occupied files or graph identities. Turtle uses the filename convention; other supported RDF sources receive a manifest association while preserving existing manifest bytes. `shapes list [--source <path>]` and `model schema list <concrete-path>` expose available support. The browser supplies the same lists, previews, confirmation and selected/whole validation through authenticated shared operations.

`impact <ontology|model|shapes|model-type> <selector>` is read-only. For graph resources it reports each exact occurrence of the graph root and declared class, property, datatype, or individual IRIs in known owned and retained locked RDF, plus exact configuration values in `tbspec.toml` and `tbspec.lock`. It also reports affected files and model bindings. The inventory does not inspect arbitrary project files, search prefixes or substrings, or infer external uses. Impact results are informational; each mutation takes its own coherent capture and rechecks exact revisions before publication.

`ontology remove`, `model remove`, `shapes remove` and `config model-type remove` first return a preview and require `--confirm`. Optional `--accepted-preview <digest>` binds CLI confirmation to the reviewed plan. Graph removal deletes only the owned graph file: it retains incoming RDF triples, neighboring support files, models and unrelated configuration. Custom model-type removal edits only its manifest row and keeps affected model files and literals. These operations can therefore succeed while leaving the project semantically invalid; the result reports validity and introduced diagnostics. Built-in model types cannot be removed. Malformed inputs, unsafe paths, stale revisions and transaction failures still refuse publication.

`resource move <owned-selector> <destination>` previews an owned graph move. The source and destination keep the same RDF format. Existing convention-linked Turtle shapes move with the graph, and known manifest path selectors move with both files; graph IRIs and terms otherwise remain exact. The preview discloses generated graph-identity changes caused by the destination path. Apply with `--apply --accepted-preview <fingerprint>` from the exact preview. Occupied destinations and graph-identity collisions refuse publication. The browser has matching impact, removal and move previews in the Resources and Configuration workspaces and applies their session-owned staged plans through the shared transaction boundary.

`src/project.ts` provides `initializeProject`, canonical upward/explicit `discoverProject`, coherent `readProject`, surgical `setProjectBaseIri`, and read-only `inspectRecovery`. Explicit project selection requires a manifest at that root and never falls back to another project. Manifest/lock incompatibility and corrupt/missing snapshots fail without migration, repair or acquisition. Missing starter defaults never fall back to the installed release. The common metadata binding is independent of current model-type overrides.

`capture`, `preparePlan` and `publishPlan` in `src/transactions.ts` are the trusted adapter boundary for later operations. Capture exact file/absence revisions and disclosed inventories, release the operation lock during computation/review, then publish the prepared plan with the same revisions. Capture every input and destination used by an operation; declare inventory scopes when discovery affects a plan. Low-level publication accepts only trusted in-process plans, never an HTTP/client-supplied write plan. Each higher-level operation remains responsible for semantic policy, locked-versus-owned resource authorization and its acceptance flags.

The version-1 schemas, source contexts, byte/graph/interpretation signatures and canonical encoding follow the [normative contract](../.scratch/mvp-technical-architecture/contracts/file-and-output-schemas.md). Human TOML setting changes replace a verified source span and reparse it, preserving unrelated content. Unsupported source syntax fails without rewriting the document.

The MVP rejects userinfo, query strings and fragments in persisted HTTP(S) source/effective URLs, HTTPS Git provenance and HTTP(S) parser bases, including empty `?`/`#` delimiters and inherited source contexts. Authentication must use transient inputs or trusted external providers. Public query URLs such as `?format=ttl` and signed redirects are unsupported; components are never stripped to manufacture a stable URL or change the RDF base. Rejection messages do not echo supplied URLs or secret values. URL syntax cannot detect every capability secret embedded in a path/host; those sources remain unsupported. RDF graph identities and terms retain their exact IRIs. Existing version-1 locks containing prohibited URL components fail without automatic rewriting; bundled initialization is unaffected. General acquisition and redirect handling belong to ticket 08.

## Local web workspace and lifecycle

Build before using web. The package contains prebuilt React/Vite assets; neither Vite nor a development server runs during installed use. The server loads its interface assets plus the inspection and dependency workers before readiness. The inspection worker handles one inspection at a time; overlapping reads return conflict/3 (`PROJECT_BUSY`, HTTP 409). Dependency operations serialize in their own worker, keeping acquisition and RDF work off the server listener. There is no waiting queue for inspection. Its provisional old-generation heap limit is 512 MiB, based on the linked synthetic checks, not representative project calibration or a total-memory ceiling. Inspection retains only the requested parsed graph. Workers parse RDF, acquire explicit dependency sources, and serialize project envelopes off the control listener. If a worker terminates, the current request fails without automatic replay; a subsequent operation recreates it after normal coordination confirms no retained lock or pending transaction recovery. Server identity and tab credentials remain valid. A global memory failure can still terminate the entire process and requires a server restart. Stop before replacing an installed package in place, including before worker recreation could load replaced modules.

The [approved assumption review and capacity measurements](../.scratch/mvp-implementation/issues/02-inspect-project-and-authenticated-web.md#approved-assumption-review-2026-10-10) record successful list/show at 250,000 synthetic triples and recoverable worker failure at 500,000 with this setting. Triple count alone does not define a supported size; representative project and platform calibration remains pending.

`web [--port <1-65535>]` starts a separate Node process or reconnects to the verified existing instance for the canonical project. The foreground CLI attaches a bounded recent-log/control console: enter `detach` to leave the server running, or press Ctrl+C to request verified graceful shutdown. Closing a browser or losing a terminal/console does not stop the server. `--background` and `--json` return readiness without attachment; JSON emits exactly one envelope without log stdout. Non-TTY execution never prompts; it attaches until interruption, external stop or stream loss/EOF. `web status` neither starts nor attaches; absent status/stop succeeds. Different projects have independent servers, and a conflicting explicit port never selects another port.

Runtime registration at `.tbspec/runtime/web.json` and its runtime directory are confined and protected to the OS user (owner-only Unix permissions, checked macOS ACLs and checked Windows DACLs). Startup preserves existing permissions on the project root, `.tbspec` and dependency snapshots. The root and `.tbspec` must belong to that user and prevent other users' writes so they cannot replace runtime storage; read access by others is accepted. Shared writable parents fail without permission changes. macOS ACL inspection uses the [native ACL API](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/acl_get_file.3.html) through built-in JXA. Non-owner grants are rejected on runtime storage; parent grants are limited to read/search rights. Lookup failures and unsupported ACL output fail closed, and existing ACLs are preserved. This does not promise support for every shared-project layout or simultaneous servers for different OS users. Privileged OS administrators can bypass user isolation. Registration is independent of the short-lived operation lock: claims, replacements and comparison/removal hold a separate `.tbspec/runtime/registration.lock` using the same full process ownership checks. Contenders recheck for up to 30 seconds; an abandoned or incomplete guard is preserved for manual recovery, without removing registration. Before health or control, the CLI verifies root, instance, host/boot/PID/start identity, protocol and authenticated handshake. Unknown/incompatible records are preserved with conflict/3; a verified live but unreachable service reports unavailable/4. Only startup may remove a guarded registration whose owner is demonstrably ended; transaction/operation-lock recovery remains manual. A failed stopping-registration write leaves reads available and permits an explicit stop retry; shutdown is not replayed after it has begun. Stop succeeds only after both process shutdown and owned-registration release are verified.

The listener binds `127.0.0.1` and checks the actual Host and exact Origin without trusting proxy headers or enabling CORS. Browser project APIs and native control APIs use separate bearers. Obtain a transient opening link through `web` or `web status`: its single-use fragment expires after 60 seconds and is removed by the client before loading the application. The exchanged tab bearer lasts 12 hours or until restart, remains in tab memory/session storage and never reaches cookies/local storage or project files. Do not archive opening links. A canonical base URL alone does not authorize access. Public assets and unauthenticated errors disclose no project paths/data; project source renders as text under a restrictive CSP.

HTTP project endpoints are `/api/project/v1/status`, `/graphs`, `/graph?selector=...`, `/editor?selector=...`, `/config`, `/model-types`, `/ontologies`, `/ontology?selector=...`, `/models`, `/model?selector=...`, `/dependencies`, `/dependency?id=...` and read-only `/impact?kind=...&selector=...`, with bearer authorization and `X-Tbspec-Schema-Version: 1`. Same-origin authenticated POSTs to `/ontology/create`, `/model/create`, `/ontology/import`, `/model/import`, `/resources/remove`, `/resources/move`, `/editor/delete`, `/dependencies/inspect`, `/dependencies/add`, `/dependencies/update`, `/dependencies/rename`, `/dependencies/remove`, `/dependencies/support/set` and `/dependencies/support/clear` return staged previews. Rename accepts `{from, to, operationId?}` and reports selectors, choices, paths, and generated identity changes; remove accepts `{id, operationId?}` and reports known owned/locked references and resulting validity. Both apply through `/dependencies/apply` with the exact reviewed fingerprint; removal requires `accept: ["confirm"]`. `/editor/delete` accepts only `selector`, the inspected source `revision`, and an exact IRI or scoped blank-node `element`; its preview lists exact source statements, known references and files affected. Apply deletion through `/resource/apply` with `accept: ["confirm"]`. `/dependencies/apply` accepts exactly `{schemaVersion: 1, handle, fingerprint, accept: []}`; `/dependencies/cancel` accepts an operation ID or preview handle. `/editor/save` accepts only `selector`, `revision`, and either `sourceText` or `edits` with optional `creation`. `/resource/apply` accepts exactly `{schemaVersion: 1, handle, fingerprint, accept: []}`, and `/resource/cancel` accepts `{schemaVersion: 1, handle}`. ## Publication and recovery

The exclusively created `.tbspec/operation.lock` records a random acquisition token and OS host, boot, PID and process-start identity. Contenders fail immediately; partial, abandoned or unverifiable records remain untouched. Normal release verifies the entire record and process identity. The root may be selected through a junction, but internal links/junctions, multiply linked writable files, aliases, invalid portable paths and case-equivalent destinations are rejected.

Transactions stage complete proposed bytes, exact before-images and a progress journal beneath `.tbspec/transactions/` on the local filesystem. Replacements use native rename; creates and move destinations use exclusive native linking of staged bytes, then remove the temporary link. Recheck inputs before publication and affected paths before actions. Normal failures roll back in reverse order, preserving intervening edits. Interrupted/incomplete rollback blocks subsequent operations and retains evidence. Completed cleanup failure returns success with `CLEANUP_RETAINED` warning.

For manual recovery, stop all project CLI/web processes and prevent new invocations. Preserve the lock, journals and originals. Use `inspectRecovery` or direct read-only filesystem inspection to identify affected paths and incomplete artifacts. Restore or explicitly accept a coherent project state before clearing retained evidence. Leave the lock if exclusive access cannot be established. There is no automatic clearing or crash replay, no persistent undo history, and no multi-file crash/power-loss atomicity claim. The coordination guarantee assumes ordinary local filesystems and cooperating tool processes; hostile writers and network filesystems are outside it.

Windows identity uses MachineGuid, OS boot time and process start time through built-in PowerShell. Linux uses machine-id, kernel boot ID and `/proc` process-start ticks. macOS arm64/x64 uses the IOPlatformUUID from built-in `/usr/sbin/ioreg`, binary `/usr/sbin/sysctl` boot-time observations and `/usr/bin/osascript` JXA to call the numeric kernel process query without a compiler or native npm addon. It preserves start-time microseconds, checks the returned PID/live state, and accepts only the verified LP64 layouts (16-byte timeval, 648-byte kinfo record); unavailable facilities or unexpected layouts fail closed without falling back to a PID or second-resolution `ps` output. See the [Apple source research](../.scratch/mvp-technical-architecture/research/macos-process-identity-contract.md) for the ABI, transport and clock-adjustment limitations. The caller verifies its own identity before creating coordination files, so an unavailable identity does not leave an empty operation lock. Existing unknown locks remain untouched.

Native macOS checks established Darwin 25.6.0 arm64 and Darwin 24.6.0 x64 execution, with 648-byte process records and 16-byte timevals, independent-owner verification and terminated-owner rejection.
