# Domain Docs

The engineering skills use a single-context layout for this repo.

## Before exploring, read these

- `CONTEXT.md` at the repo root for domain terms.
- Relevant decisions in `docs/adr/`.

If either is absent, proceed silently. Create domain docs when terms or decisions are actually resolved.

## Layout

- `CONTEXT.md`: the repo's domain glossary.
- `docs/adr/`: architectural decisions.

## Use the glossary's vocabulary

Use the terms defined in `CONTEXT.md` in issues, proposals, hypotheses, and tests. If a needed term is absent, reconsider the wording or note the gap for domain modeling.

## Flag ADR conflicts

If a proposal contradicts an existing ADR, identify the conflict explicitly.
