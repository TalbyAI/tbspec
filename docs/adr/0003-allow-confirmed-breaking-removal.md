# Allow confirmed removal that breaks references

Before deleting a model type or resource, the tool shows incoming references and affected files. The user can then confirm the deletion even if those references remain. When removal breaks a managed association, required vocabulary, view/presentation invariant, or explicit constraint, validation and project status report the resulting invalid state until those errors are repaired. Ordinary individual-valued IRI occurrences are disclosed in impact but do not require local targets merely because a local individual was deleted; the [managed-reference scope contract](../../.scratch/mvp-technical-architecture/contracts/file-and-output-schemas.md#managed-reference-scope) defines the distinction without a deleted-identity registry. The CLI supports previewed redirection or removal of dangling references; invalid RDF syntax must first be corrected in the source file. Orphaned project-owned support resources remain until a separate, confirmed garbage collection removes them. Independent designs and locked dependencies require their own removal commands. This keeps deliberate restructuring possible without a silent cascade. Projects using Git rely on it for history; the tool does not implement a second revision system.
